3.1. Diseño General:

Arquitectura basada en microservicios con una aplicación Flask que actúa como intermediario entre clientes HTTP y servidores SFTP. La aplicación recibe solicitudes HTTP y realiza conexiones SFTP para transferir archivos.

3.2. Capas y Módulos:

  • Capa de Presentación: API REST con Flask
  • Capa de Servicios: Lógica de negocio para manejo de conexiones SFTP
  • Capa de Acceso a Datos: Cliente SFTP usando Paramiko

3.3. Patrones de Diseño:

No especificado

3.4. Flujo de Datos Principal:

  1. Cliente HTTP realiza solicitud GET a la API
  2. Flask procesa la ruta dinámica /<compressed_file>/<filename>
  3. La aplicación establece conexión SFTP con servidor remoto
  4. Se descarga el archivo solicitado desde el servidor SFTP
  5. El archivo se devuelve como respuesta HTTP al cliente
