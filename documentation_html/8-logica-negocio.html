8.1. Flujos de Trabajo Importantes

Flujo 1: Conexión SFTP Segura

Propósito: Establecer una conexión segura con el servidor SFTP para operaciones de transferencia de archivos.

Pasos del flujo:

  1. Lectura de Configuración: Cargar parámetros de conexión desde el archivo config.json
  2. Validación de Credenciales: Verificar que todos los parámetros requeridos estén presentes
  3. Establecimiento de Conexión: Usar Paramiko para crear conexión SSH/SFTP
  4. Autenticación: Validar credenciales con el servidor remoto
  5. Verificación de Estado: Confirmar que la conexión esté activa y operativa

Flujo 2: Descarga de Archivos Comprimidos

Propósito: Descargar archivos específicos desde el servidor SFTP hacia el sistema local.

Pasos del flujo:

  1. Recepción de Solicitud: Endpoint Flask recibe parámetros de archivo
  2. Validación de Parámetros: Verificar que compressed_file y filename sean válidos
  3. Establecimiento de Conexión SFTP: Ejecutar flujo de conexión segura
  4. Navegación de Directorios: Acceder al directorio especificado en compressed_file
  5. Búsqueda de Archivo: Localizar el archivo específico por filename
  6. Descarga: Transferir archivo desde servidor remoto a local
  7. Validación de Descarga: Verificar integridad del archivo descargado
  8. Respuesta al Cliente: Retornar archivo o mensaje de error

Flujo 3: Manejo de Configuración Externa

Propósito: Gestionar la configuración de la aplicación de manera flexible y segura.

Pasos del flujo:

  1. Detección de Archivo de Configuración: Buscar config.json en directorio raíz
  2. Validación de Estructura: Verificar que el JSON tenga estructura esperada
  3. Carga de Parámetros: Leer y parsear configuración a variables internas
  4. Validación de Valores: Confirmar que todos los parámetros requeridos estén presentes
  5. Disponibilidad para la Aplicación: Hacer configuración accesible a todos los componentes

Flujo 4: Logging de Errores

Propósito: Registrar eventos de error para diagnóstico y monitoreo.

Pasos del flujo:

  1. Detección de Error: Capturar excepciones en cualquier punto del flujo
  2. Clasificación: Identificar tipo y severidad del error
  3. Registro en Archivo: Escribir en error.log con timestamp y detalles
  4. Manejo de Error: Decidir si continuar operación o retornar error al cliente
  5. Respuesta al Usuario: Proporcionar mensaje de error apropiado

8.2. Componentes Clave Involucrados

Controlador Principal (app.py)

Responsabilidad: Manejar las solicitudes HTTP y coordinar los flujos de trabajo.

Métodos y Funciones Principales:

  • Endpoint Dinámico: GET /<compressed_file>/<filename>
  • Gestión de Rutas: Definición y manejo de la ruta principal de la API
  • Coordinación de Flujos: Orquestar la secuencia de operaciones SFTP
  • Manejo de Excepciones: Captura y registro de errores

Servicio de Conexión SFTP

Responsabilidad: Gestionar toda la lógica de conexión y transferencia SFTP.

Funcionalidades Clave:

  • Autenticación: Manejo seguro de credenciales SFTP
  • Transferencia de Archivos: Operaciones de upload/download
  • Gestión de Sesiones: Apertura y cierre de conexiones
  • Navegación de Directorios: Exploración del sistema de archivos remoto

Servicio de Configuración

Responsabilidad: Cargar y validar la configuración de la aplicación.

Componentes:

  • config.json: Archivo de configuración externo
  • Parser JSON: Lectura y validación de la configuración
  • Validación de Parámetros: Verificación de configuración completa

Servicio de Logging

Responsabilidad: Registrar eventos y errores de la aplicación.

Componentes:

  • error.log: Archivo de registro de errores
  • Sistema de Logging: Mecanismo de escritura de logs
  • Formato de Logs: Estructura consistente para mensajes de error

Interacciones entre Componentes


Flujo de Descarga de Archivo:
1. Cliente → Controlador Flask (solicitud GET)
2. Controlador → Servicio Configuración (cargar parámetros SFTP)
3. Controlador → Servicio SFTP (establecer conexión)
4. Servicio SFTP → Servidor Remoto (autenticación y descarga)
5. Servicio SFTP → Controlador (archivo descargado o error)
6. Controlador → Servicio Logging (registrar resultado)
7. Controlador → Cliente (respuesta HTTP)

8.3. Explicación del Patrón de Diseño Identificado

Patrón Identificado: Arquitectura de Microservicio Simple con Patrón Service Layer

Justificación: Aunque el proyecto es pequeño, muestra una clara separación de responsabilidades entre la capa de presentación (Flask) y la capa de servicios (lógica SFTP).

Componentes del Patrón Service Layer

1. Capa de Presentación (Presentation Layer)

Componente: Controlador Flask (app.py)

Responsabilidades:

  • Manejo de solicitudes HTTP
  • Definición de rutas API
  • Coordinación general del flujo
  • Transformación de respuestas HTTP

2. Capa de Servicios (Service Layer)

Componentes: Servicios SFTP, Configuración y Logging

Responsabilidades:

  • Contener la lógica de negocio principal
  • Gestionar operaciones complejas (conexión SFTP)
  • Coordinación entre diferentes subsistemas
  • Validación de reglas de negocio

3. Capa de Infraestructura (Infrastructure Layer)

Componentes: Paramiko (SFTP), Sistema de Archivos, Configuración Externa

Responsabilidades:

  • Proveer implementaciones técnicas concretas
  • Gestión de recursos externos
  • Comunicación con sistemas externos

Implementación del Patrón en el Proyecto


# Ejemplo de estructura de interacción entre capas

# Capa de Presentación (Controlador Flask)
@app.route('/<compressed_file>/<filename>')
def download_file(compressed_file, filename):
    try:
        # Delegar a capa de servicios
        file_content = sftp_service.download_file(compressed_file, filename)
        return send_file(file_content)
    except Exception as e:
        # Delegar logging a servicio especializado
        logging_service.log_error(str(e))
        return error_response(str(e))

# Capa de Servicios (Servicio SFTP)
class SFTPService:
    def download_file(self, directory, filename):
        # Lógica de negocio: validaciones, reglas
        config = config_service.load_config()
        connection = self.establish_sftp_connection(config)
        file_content = connection.get_file(directory, filename)
        return file_content

# Capa de Infraestructura (Paramiko SFTP)
class SFTPConnection:
    def get_file(self, directory, filename):
        # Implementación técnica específica
        return self.sftp_client.get(f"{directory}/{filename}")

Características de la Arquitectura Identificada

  • Separación de Responsabilidades: Cada capa tiene un propósito específico
  • Bajo Acoplamiento: Las capas se comunican a través de interfaces claras
  • Testabilidad: Facilita pruebas unitarias de cada componente
  • Mantenibilidad: Cambios en una capa no afectan necesariamente a otras

Ventajas del Patrón Implementado

  • Escalabilidad: Fácil agregar nuevos servicios sin modificar el controlador principal
  • Reusabilidad: Servicios SFTP pueden ser utilizados por otros componentes
  • Mantenibilidad: Lógica de negocio centralizada en servicios especializados
  • Flexibilidad: Fácil cambiar implementación de SFTP sin afectar la API
